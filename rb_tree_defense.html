Red-Black Tree Defense

Your server's index is a binary search tree. Data packets are flooding in. Each one slides down the tree (smaller ← → larger) and docks as a red leaf.

  • Click a node, then Left Rotate, Right Rotate or Recolor it.
  • The moment the whole tree is a valid red-black tree, GC wipes out every docked packet.
  • Let it lean: latency spikes eat your memory. Too deep: Stack Overflow.

Insert fix-up cheat sheet
  1. Uncle red: recolor parent + uncle → black, grandparent → red. Repeat higher up.
  2. Uncle black, zig-zag (node is inner child): rotate the parent outward so it becomes a straight line.
  3. Uncle black, straight line: parent → black, grandparent → red, rotate the grandparent the opposite way.
  4. Finally make the root black.

How to play

Packets (purple hexagons) enter at the top and walk down the tree by BST rules: smaller goes left, larger goes right. When they hit an empty slot they dock as a red node with a toxic dashed ring. Docked packets are dormant for a few seconds, then start leaking memory.

Whenever the entire tree satisfies every red-black rule, the tree lights up, Garbage Collection fires and every docked packet is destroyed for points. Clear a wave (all packets collected, tree valid) to compact memory and pick 1 of 3 patches.

Red-black rules

Rule 2The root is black.
Rule 3Empty (NIL) leaves count as black — always true here.
Rule 4A red node never has a red child (orange pulsing edge).
Rule 5Every path from a node down to a NIL leaf passes the same number of black nodes (yellow bh badge marks mismatches).

Failure modes

Latency spikeTree depth H > 2·log₂(N+1): memory drains every second, faster the deeper you go.
Stack OverflowH exceeds the call-stack limit (12 levels): instant crash.

Rotations

Left Rotate(x): x's right child y moves up into x's place; x sinks to become y's left child; y's old left subtree becomes x's right subtree. Right Rotate is the mirror image. In-order (sorted) order never changes.
